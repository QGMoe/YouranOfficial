# 第 8 个彩蛋游戏「挖穿」（id: breach，文件 08-breach.js）— 服主设计（整理稿）

> 以下是服主口述设计的整理，所有"服主："引号内为原话要点。实现细节可以由 agent 决定，但不得违背这里的设计。

## 1. 背景与目标
- 人工鱼骨式矿洞里挖矿，挖穿到岩浆。岩浆源源不断、压强很大（背后是很深的岩浆湖）。
- 玩家用 WASD（手机用方向按钮，键盘控制保留）在矿洞迷宫里找到出口的梯子逃出去。
- 2D 俯视视角，但底层用三维格子计算流体。
- 场景不要太大，否则算不过来。

## 2. 三维结构（服主已确认）
- 巷道高 2 格（玩家 2 格高），矿坑在地面下 1 格，上方是实心岩层。
- 岩浆湖在破口后面，湖面高于巷道顶部，所以压强能把巷道灌满，同时不违反"压强瞬移不超过源头高度"。
- 源头视为无限：源头格每次更新都补满。

## 3. 流体物理（必须参考服主的有限流体算法）
- 参考理解报告：`../geocraft-fluid/理解.md`（尤其 §2 更新顺序、§3 压强系统、§7 伪代码）。代码在 `/home/user/qgmoe/geocraft`（只读）。
- 层（Quanta）为整数，每格 8 层；规则顺序：竖直下落 → 压强流动 → 单层坡度 → 平均流动 → 转静态并发布压强任务；静态格被随机刻/邻居更新/压强回调唤醒。
- 压强系统：有界 BFS，只走同种流体、空气只作终点、不超过源格高度；结果按 BFS 顺序瞬移（同高平分差、低处尽量填满/整格搬走）。服主强调："压强活跃的时候再慢的更新岩浆都会流得很快"——难度不能只靠降低更新频率来调，必须理解压强瞬移会让岩浆快速推进，要从压强参数（BFS 规模/回调延迟/结果数上限）、破口位置、源头高度等综合调节节奏。
- 守恒：除源头补给外，流动过程严格守恒（整数层）。
- **异步**：服主："我感觉可以跑异步，浏览器可以吧？"——用 Web Worker 跑流体模拟（可以在单个模块文件里用 Blob URL 创建 Worker，不额外增加文件；若做不到需说明）。主线程只负责输入、渲染和插值。测试时提供同步、确定性的模式。

## 4. 岩浆深度与伤害（服主：按层数）
- 伤害/减速按所在格的岩浆层数分级（具体曲线由 agent 设计，层数越高越危险；没过头部（2 格都有岩浆）=很快死亡）。
- **2D 俯视下如何表现层数需要精心设计**（服主原话）。先出 3 个以上可视化方案的效果图给服主选，再定稿。
- 有生命值（因为信标有生命恢复）。

## 5. 视野与光照
- 大部分巷道有火把；难度越高越会出现无火把区域（不做怪物）。
- 玩家左手拿火把，能看清身边一小圈。
- 岩浆自身发光（照亮周围）。岩浆流过火把会烧掉火把（agent 前一轮的提议，可做）。

## 6. 迷宫（服主：要真实）
- 人工鱼骨式：横平竖直的主巷道 + 两侧支巷；偶尔打通形成环路，也有死路。
- 要有细节：偶尔有挖剩的矿物、遗落的东西等。
- 由 ctx.seed 确定性生成；难度（ctx.cycle）越高迷宫越大、无火把区越多、矿坑越多、岩浆越快、破口离起点越近（服主确认）。
- 越靠近出口：矿坑越多、未挖掘的矿物越少、火把越多（这里是常有人活动的区域）。
- 梯子旁有一个小厅，里面有箱子（装饰），表示这是一个站点。

## 7. 矿坑
- 矿道里随机出现矿坑（地面下 1 格）。不小心掉入后需要朝正确方向长按才能爬出来（时长随难度略增，起步约 0.8 秒）。
- 岩浆会优先灌进矿坑；人在坑里被灌到就按层数伤害处理。

## 8. 出口提示
- 气流：岩浆是热的，气体受热膨胀，吹向出口（洞口）——做气流流动的视觉效果，指示出口方向。
- 靠近出口时有光。
- 配合 §6 的"越靠近出口越热闹"的环境渐变。

## 9. 信标
- ~~游戏偶尔在某些地方刷新信标，信标给玩家提速和生命恢复效果。~~ → **服主修订**：信标固定在专门的信标厅中央（实心、不能拾取）。厅是两条主巷道之间扩出来的 5×5（常见）或 7×7（罕见，范围与时长更大）；地面为石砖。
- 光环：在范围内（以信标为中心切比雪夫距离 ≤ 3 / 4 格）自动获得提速与生命恢复，持续刷新；离开后倒计时（5×5 约 6 秒、7×7 约 12 秒）结束才消失。HUD 显示效果图标与剩余时间。
- 光柱：从信标向上射出、冲出画面顶部（3D 为加法混合的发光面片，不受墙体渐隐 / 镂空影响；2D 为画面上方的光束），reducedMotion 时静止。
- 每层信标厅数随难度减少（低档 2 个、高档 1 个），7×7 概率随难度降低；厅不放坑、积水、火把，全层连通、梯子可达（信标按实心计）；开局预跑的公平判定不使用信标。

## 10. 梯子与结局
- 到达梯子后需要长按（方向键/按钮）攀爬。这时切换整个游戏的显示：变成中心有梯子、玩家在上升的视图（竖井侧视）。
- 如果玩家刚开始上升时岩浆已经抵达梯子，底下要做岩浆也在上升的效果；难度越高岩浆上升得越高，直到达到一个静压面（与源头/压强决定的液面高度一致）停止。
- 玩家爬出后到达原版风格的草原，完成游戏。
- 出口序列（服主追加）：最后一段竖井近地面时井壁由石头过渡为 3 格泥土、最上面一格草方块，地面以上是天空与远景（结局同一张原创像素背景，3D 里作为整屏贴图铺在地形后面，地平线对齐地表）；爬出后不黑屏，直接从井口附近拉远到整幅草原（约 2.4 s），拉远结束后结算面板才淡入；减少动态时不拉远、面板立即出现。2D 兜底同样画泥土/草方块/天空，并共用拉远镜头。
- 结算面板（服主追加）：像素风面板（双层描边 + 标题栏），宽舞台叠在草原画面下方、窄舞台放在舞台下面，都不挡城区轮廓；失败时叠在死亡瞬间的画面上。内容：胜负标题与原因（回到地面 / 被岩浆吞没 / 溺水）、大号用时、最佳、新纪录徽章（像素闪光，减少动态时静止）、5 项统计（逃出层数、最低生命、掉进矿坑、经过信标、泡在流体里的秒数或离流体最近的格数）、版本号与难度档；按钮"再来一次"（`<button>`，同一张图）与"下一张图"（`<a href=ctx.href(1)>`，`null` 时隐藏），胜利时主按钮是"下一张图"、失败时是"再来一次"，出现时焦点落在主按钮上；淡入上滑，减少动态时立即出现。

## 11. 负数版本：地下水
- 负数 n 时，挖到的不是岩浆而是地下水。水的不同：
  - 不发光；
  - 会冲掉火把；
  - 流得可能更快一点；
  - 玩家只有在完全被水淹没时，右下角出现气泡；气泡耗尽才结束（不受层数伤害）。
- 其他一样（迷宫、梯子、信标等）。
- 竖井上升阶段同理换成水上升。
- 溺水（服主追加）：气泡用完后人物失去控制（移动、QTE、挖矿等输入都不再生效，手脚慢慢扑腾；减少动态时不动），画面黑暗从四周往中间收拢，生命不论还剩多少都在约 3.5 s 内加速扣完，然后以"溺水"失败结束（之后照常等结算面板淡入才接受开新局）。声音变闷，伴随越来越慢的心跳。表现矿难的绝望感：一旦气泡用完就无法挽回。3D 与 2D 一致。岩浆不受影响。

- 键盘：WASD 与方向键；长按用于爬出矿坑与爬梯子。
- 手机：屏幕方向按钮（支持长按），不代替键盘。

## 14. 正数场景中的地面积水（服主追加）
- 正数（岩浆）场景里也可以出现摊在地面上的水（浅积水，参与同一套流体模拟）。
- 玩家经过积水会变慢。
- 岩浆碰到水会反应变成石头（按 GeoCraft 的水–岩浆混合规则，见理解报告相关章节与源码），石头是实心方块。
- 因此岩浆在这里需要涨到"一层多"的深度（高过新生成的石头）才能越过去；同样的道理，玩家也越不过去（石头挡路）。
- 这会让积水成为改变岩浆路线的天然屏障，同时也可能堵死玩家的路——迷宫生成要保证：积水的位置与数量不会让"起点→梯子"在岩浆反应后必然无解（例如积水不放在唯一通路的必经瓶颈处，或该处存在绕行路线）。

## 15. 气流的成因随场景不同（服主确认）
- 共用一套"气流场"：沿巷道走向出口的气流，强度由"驱动源"决定，只是驱动源与表现不同。
- 岩浆场景（热膨胀）：岩浆加热空气、空气膨胀从洞口排出。强度取决于热量（靠近岩浆、岩浆接触面积越大越强）；岩浆停止推进后只要还热就一直吹。表现：暖色热浪扭曲 + 火星/灰烬飘向出口。
- 地下水场景（排挤空气）：水不让空气膨胀，但灌进矿洞会把空气挤出去，方向同样朝出口。强度取决于进水速度（每次更新新增的水量），水面稳定后风渐渐停——"风停了=水已灌得差不多"本身是提示。表现：冷色、潮湿气流，水汽/细小水滴飘动，无热浪扭曲；可加顶部滴水作环境细节。
- reducedMotion 时用静态的方向指示代替飘动粒子，提示功能不能丢。

## 16. 计时（服主追加）
- 要有计时：从点"开始"起算，爬出竖井到达草原时停止；竖井攀爬阶段照常计时。
- 页面隐藏/暂停时计时暂停（用模拟时间，不用墙钟），保证公平。
- HUD 常驻显示用时（精确到 0.1 秒）；结算画面显示本次用时和最佳用时。
- 最佳用时按地图记录（同一个 n 即同一张图，key 含 seed 与 cycle），失败不记录。

## 17. 多层矿道（服主追加，较高难度）
- 较高难度时：爬上梯子后不是直接到地面，而是到了更高的另一层人工矿道（第二层），流体随后从梯子竖井那边涌上来，玩家要在这一层继续找梯子。
- 越难层数越多，最多三层；最后一层的梯子通往地面草原（§10 结局）。层数随 cycle 的阈值由 agent 提出、服主确认。
- 越往上层矿物等级越低（深层：钻石/金/红石/青金石等；上层：铁/煤为主）。
- 物理一致性：流体能从竖井涌进上一层，前提是静压面（源头高度）高于该层地面——所以层数越多，源头/岩浆湖的高度设定越高；涌入上层的流体同样遵守压强系统（不超过源头高度）。若静压面只到某层中间，就只淹到那里。
- 竖井攀爬（§10 的侧视切换）在每次换层时都出现；流体在竖井中上升到静压面为止。
- 计时（§16）贯穿所有层，不分段重置；HUD 显示当前层数。
- 性能：只对当前层 + 竖井做完整模拟，下层可以冻结为竖井底部的源头边界条件（说明这样的近似为什么不违背设计）。
- 每层都是独立生成的鱼骨式迷宫，共用 §6 的规则；上层的入口（竖井口）就是流体涌出的位置，出口梯子要离入口足够远，且不能让玩家一出竖井就无路可逃（给出最小安全距离/首次压强回调延迟等参数）。

## 18. 深矿坑连通下层（服主追加，修订 §17 的"下层冻结"）
- 第二、三层有少数矿坑特别深，向下连通到下一层的巷道。
- 当下一层已被灌满（流体在连通处达到足够高度、且静压面高于本层地面）时，流体也会从这些深矿坑涌出来——成为本层的第二、第三个涌出点。
- 如果玩家速度快，离开下一层时那里还没灌满，这些深矿坑的涌出就相应推迟：涌出时间由下一层的实际灌注进度决定，不是固定计时器。
- 因此 §17 的"下层冻结为竖井底部边界"要修订：玩家离开后，下一层仍要继续模拟灌注（可降低频率、可粗化，但必须保持守恒与压强规则的定性一致），直到它对本层的连通点（竖井 + 深矿坑）达到稳定。说明采用的近似和误差。
- 深矿坑在俯视图上要和普通矿坑明显区分（更深更暗、能隐约看到下方）。玩家掉进深矿坑：~~采用"更深、需要更长时间长按才能爬出"的处理（不掉回下一层）~~ → **服主修订**：掉进深矿坑后扒住坑沿，出现抓握条（时长 = 爬出所需长按时间 + 余量，余量随难度从约 1.4 秒降到 0.6 秒）；期间朝能走的方向长按爬出，抓握条用完就掉到下一层同一格（短暂下坠 + 淡出淡入，落地扣 3 点生命、不致死；下层一直在模拟，落进流体按层数伤害 / 溺水规则）。只对深矿坑生效，普通矿坑不变；开局预跑的理想路线不经过深坑，公平判定不受影响。若此时流体从下方涌上，危险程度按层数伤害/溺水规则计算。
- 迷宫生成：深矿坑数量少，且不能放在本层入口附近导致一出竖井就被两面夹击；与出口梯子的距离也要合理。

- 深坑 QTE（服主追加）：掉进深坑后先有一次极短的快速反应——人物周围收缩的方框 + 下方快速见底的条，写"空格"（触屏写"点击"）。桌面按空格、触屏点一下画面（方向键、方向按钮都不算）；成功才扒住坑沿进入上面的抓握 / 长按爬出阶段，超时直接掉到下一层（同一格、−3 生命、下层流体照常）。时限在 `tier(d).qte`：第 0 档 1.0 s → 第 28 档 0.5 s，随档位单调变短。QTE 进行中空格阻止默认行为（不滚动页面），游戏进行中画布有焦点时空格也不滚动、不会开局/重开。开始时有提示音，接住时有扒住的声音；减少动态时没有收缩方框与抖动，只有见底的条。预跑路线按"接住"计时（理想路线），自动驾驶（测试用）总是接住。

- 深坑往下看（服主追加，落实上面"能隐约看到下方"）：人物附近（3 格内）有深坑时，俯视画面沿坑口→下层地面方向开一扇"观察窗"，窗内比坑中轴更靠近镜头的地面与坑壁渐隐；坑壁一直画到下层地面，下层地面与相邻的下层巷道、坑里真实的流体（从下层一直到当前层地面，岩浆发光并照亮坑壁、水有水面）都看得见；当前层地面以下越深越暗（深度雾）。坑口的辉光/涟漪预警保留。2D：深坑里的流体颜色与高度从下层脚部算起。

## 19. 涌出时机一律由模拟决定 + 深坑预警（服主追加）
- 不只是深矿坑：**竖井的涌出**也一样——玩家越早跑到上一层，流体从竖井涌出的时间就相应越晚。所有涌出点（竖井、深矿坑）的时机都由下层流体的实际推进与灌注决定，禁止用固定计时器或"玩家进入上层后 N 秒"之类的规则。
  - 例：玩家在岩浆还没到达梯子时就爬上去 → 竖井里此时没有岩浆，上层暂时安全；直到下层岩浆真的漫到竖井底并在压强作用下升到上层地面以上，才从竖井口涌出。
  - 竖井攀爬侧视（§10）中"岩浆跟着上升"也只在流体确实已抵达竖井时出现。
- 深矿坑预警：下一层的流体在深坑里上涨、快要涌出但还没涌出时，俯视图要能看到坑底的情况——例如坑内逐渐升高的岩浆亮光（越接近越亮、越近坑口）/ 水面反光上升，让玩家提前察觉。水（负数场景）不发光，需要用水面高度/颜色/涟漪等其他方式表现。
- reducedMotion 下预警仍须可见（静态的亮度/颜色分级）。

## 20. 结局草原远景：悠然城区轮廓（服主追加）
- 灵感来源：服主在本地服务器存档备份上试装天圆地方时，城区底部的人工矿道被岩浆淹了。结局要暗示"你刚才就在城区地下"。

## 21. 算法可以为游戏做取舍（服主追加）
- 服主："不一定要完全按我的算法写，例如你可以让所有流体方块都会发布压强任务，而不是只有靠近表层的才发布。"
- 原则：保留压强系统的核心原理（有界 BFS 只走同种流体、空气只作终点、瞬移不超过源头高度、整数层守恒），其余调度细节（谁发布压强任务、发布概率/权重、回调延迟、结果清空周期、异步批次等）可以为了游戏的可玩性、可预测性和性能自由调整。
- 每一处偏离都在报告里列出：原算法怎样、游戏里怎样、为什么。
- 服主补充："如果实在比较复杂，可以简化掉一些实际上在这个场景下不怎么会用到的算法或细节。"例如：载流方块交换、蒸发/降雨/冻结、模组流体兼容、多层坡度（默认关闭）、瓶/桶等与本场景无关的部分可以直接不实现。同样在报告里列出删减项与理由。

## 22. 动画必须流畅（服主追加："动画要流畅，不然不过瘾"）
- 目标：跟随屏幕刷新率（60/120Hz）稳定渲染，中端手机上不掉帧；不能因为流体模拟而卡画面（模拟在 Worker 中，主线程只做输入 + 渲染）。
- 流体渲染插值：Worker 的模拟步是离散的，主线程要在两次快照之间对每格液面高度做平滑过渡（例如按时间插值/缓动），不能一格一格"跳"。
- 压强瞬移在逻辑上是瞬间的，但画面上要表现为一次短促的"涌动"（源头侧下降、目标侧上升的快速过渡），既流畅又让玩家看得出发生了什么。
- 玩家移动：像素级平滑移动（非逐格瞬移），有加速/减速手感；镜头平滑跟随，但最终绘制坐标取整，避免 1px 抖动（参考 runner 修复过的取整策略）。
- 竖井攀爬与草原结局的切换要有过渡动画。
- 性能手段：静态地形预渲染到离屏画布、只绘制可见区域、光照/雾用低分辨率缓冲放大、避免每帧分配对象（减少 GC 卡顿）、Worker 消息只传差量（Transferable/TypedArray）。
- 验证：用 Playwright + CPU 降速（例如 4× throttle）测帧时间分布（p50/p95/p99 和长帧数量），在报告中给出；同时逐帧检查无抖动/闪烁。
- reducedMotion：保留必要的平滑移动（这是操作反馈），去掉装饰性动画（热浪、粒子、屏幕震动等）。

## 23. 允许自托管轻量库（服主确认）

## 24. 第一阶段后的服主决定（2026-10-03）
1. 静态流体没有压强结果时：服主解释模组需要在大场景下工作所以不能一直算压强；游戏里改成**一直发布压强任务**（不必用 0.4 概率）。
2. BFS 先下、水平轮转、最后向上：同意。
3. 无限源头"泵"：同意。
4. 每张图有解：同意开局预跑；但**必须保证同一个版本号的游戏完全一样**——预跑与换破口的过程必须是确定性的（同步、固定种子、按刻计数而非墙钟、候选破口按种子确定的顺序依次尝试，取第一个满足公平条件的），与设备快慢、Worker 调度无关。同一 n 在任何设备上得到同一张图、同一个破口。
5. 竖井：**不要让梯子挡流体**。梯子做成"含水方块"（天圆地方目前还没实现的特性）：岩浆和水都可以以 1–8 层的形式与梯子同格共存。竖井改为单列（梯子格本身就是流体通道），流体在梯子格里上涨，玩家边爬边被追。侧视画面要画出梯子与液面同格（液面在梯子后/前的层次关系要清楚）。
6. 难度做成**周期性**：避免低难度只有有限几张图、高难度近乎无限。建议 `d = cycle mod P`（P = 难度档数，现为 29 → d 取 0–28，见 §25），种子仍由完整 n 决定，所以每个难度档都有无限多张图。层数/参数表按 d 查。
7. 伤害曲线：同意（1–2 层 1/s，3–4 层 2/s，5–8 层 4/s，更深 8/s，没顶 20/s）。
8. 画法：**V3 真 3D 体素（手写 WebGL2，原型见 view3d/C-webgl.html）为主，不支持 WebGL2 时退回 2D-B（液面抬升 + 水位线，配 2D-A 色阶）**。

## 25. 难度档数改为 29（服主决定；仍守"互质周期"原则）
- 各彩蛋游戏的档数选成两两互质以拉长整体周期（runner 7、redstone 23、prospect 11、creeper 21、craft 25、fishing 11、breach 29，游戏总数 8）。挖穿的 P 由 13 改为 **29**（质数，与其他档数及游戏总数都互质），整体周期 8 × lcm(7, 11, 21, 23, 25, 29) = 30,815,400。
- 档位表集中在 `core.js` 的 `tier(d)`：第 0 档 = 原 13 档版第 0 档；第 12～14 档 ≈ 原第 12 档；第 28 档最难。每一维随档位单调（只变难或持平），相邻两档至少一维变难，阶梯参数的跳变点错开。测试（maze.test.mjs）逐档检查这三条。
- 高档（第 14 档以后）加难的手段：破口更近（14 → 4 格）、湖更宽、源头压强等级更高、压强回调更快（dispersion 更小）、流体更快（TPS）、静压面更高（第 24 档起 +1）、公平放宽倍数更低（第 13 档 1.25 → 第 28 档 1.10）、矿坑/深矿坑/积水更多、爬坑更慢、深坑 QTE 时限更短（1.0 → 0.5 s）、无火把区更多且火把更稀、信标厅 7×7 更少且效果时长更短（第 28 档约为一半）、支巷更多死胡同更少成环。
- 地图尺寸不再随高档增大（第 11 档起 50×24×3，与原第 12 档相同）：开局预跑的耗时约与"淹没体积 × 路线时长"成正比，宽 53 起最坏预跑就翻倍，62×36 时单次要 2 s 以上（Node，未降速）。
- 地下水（负数版本）的流体参数（TPS、湖宽、源头压强等级、压强回调延迟）封顶在第 13 档：水流得比岩浆快得多、每刻模拟也贵得多，不封顶时高档的水几乎总在下层追上理想路线、预跑要反复换图；第 13 档以后水场景靠迷宫、破口距离和公平放宽倍数加难。
- 公平预跑：先按候选顺序试原图的破口；某个候选的失败代价大（在上层才出危险，或模拟超过 20 s 才出危险）时不再试本图其余候选。原图不满足"理想路线 × slack + 2 s 内无危险"时，按 regen = 1…7 换图重来（确定性，只由 seed 与 d 决定），8 张都不满足才取余量最大的（各档实测没有出现过）。Worker 回传 (k, regen)，主线程按同样参数重建。

## 26. 音效（服主："默认静音，尤其是挖穿需要仔细做"）
- 全部用 Web Audio 实时合成（8-bit/低保真风格，原创），不用 MC 原版音频、不加载外部音频文件。
- 由宿主统一管理开关（默认静音，记在 localStorage），游戏通过 `ctx.audio` 使用（接口见 CONTRACT，由宿主 agent 实现；挖穿按同一接口接入，开发期间可在 harness 里模拟）。静音时不得创建/播放任何声音；页面隐藏时自动静音。
- 挖穿要"仔细做"，至少包括：
  - 环境声床：矿洞底噪/低频嗡鸣；滴水（地下水场景）；火把轻微噼啪（靠近时）。
  - 岩浆：持续的冒泡与低沉轰鸣，**音量与低通随与最近岩浆前锋的距离变化**（越近越响越亮），立体声声像随岩浆在屏幕左右的位置变化；压强瞬移（涌动）时有一次明显的"涌入"声，作为危险预警（与画面涌动同步）。
  - 地下水：流水/涌水声替代岩浆轰鸣，不发光对应地，声音是玩家感知水位的重要线索；被淹没时声音变闷（低通），气泡减少时有呼吸/气泡提示音。
  - 气流：风声强度与气流场一致，越靠近出口风声越明显——作为听觉上的出口提示。
  - 动作：脚步（按地面类型：石/积水/浅岩浆区不同）、掉坑、爬出、爬梯子节奏声、受伤、信标效果（嗡鸣光环）、岩浆遇水成石的嘶声。
  - 深坑预警：下层流体快涌出时，坑口附近传出逐渐增强的低频声。
  - 竖井：攀爬节奏 + 下方流体上涨的声音逐渐逼近；到达草原时环境声切换（风、鸟鸣等自然声）作为解脱感的结束音景。
  - 混音：有主压缩/限幅，避免叠加爆音；同类声音限制并发数；所有持续声在暂停/卸载时淡出并释放节点。
- reducedMotion 不影响音效；但音效不能成为唯一的信息来源（静音时画面提示仍完整）。

## 27. 流体可以落后于游戏时间（服主决定，不是 bug）
- 流体在 Worker 里异步推进（无 Worker 时每帧最多跑 6 ms），主线程不等它；慢设备上流体可能落后游戏时间几刻，岩浆 / 水到得更晚。
- 服主："这就是天圆地方流体物理的特性"——与模组在服务器卡顿时流体变慢的表现一致，保持现状，不要让游戏时间等流体。
- 地图、破口与流体演化本身是确定的（流体状态全为整数，随机数为 mulberry32），差异只来自模拟是否跟得上。

## 28. 奇怪的矿石（服主追加）
- 术语（服主坚持，界面、文档、代码注释一律照用）：「奇怪的矿石」= 墙里可以挖的矿石方块；「奇怪的石头」= 挖到后得到的物品（"+1" 图标、HUD 计数、结算面板"奇怪的石头 ×N"、计分里的系数）。
- 来由：出自服主的模组。服务器上它真的很稀有，玩家对其他矿石不感兴趣，所以游戏里**只有奇怪的矿石能挖**（其他矿石仍只是装饰）。它的吸引力在名字和颜色：灰色石头里不合时宜的粉、天蓝、奶油色晶粒，引诱玩家冒险绕路去挖。因此晶粒带轻微自发光与闪烁（减少动态时静止），暗处、无火把区也不会被光照压成灰色，3D、2D、深浅主题里都能远远看到。
- 外观：方块贴图参照服主亲手画的 16×16 矿石贴图（灰石底 + 粉 / 天蓝 / 奶油色晶粒），程序生成；剖切顶面另有一张更稀的晶粒剖面。**物品图标是原创的 11×11 像素四角星**（收腰星形、粉 → 白 → 天蓝渐变、左上亮右下暗的棱面、深紫描边）。版权说明：模组里的物品贴图与《原神》官方的原石图标基本一致，不得复制、描摹或缩小使用；模组 jar 里的任何文件都不进仓库。
- 位置（随地图种子确定，进入地图指纹，主线程与 Worker 一致）：只在巷道**侧壁**的脚部（b+1）或头部（b+2）高度，从不在地面或顶板上，也不能从上方 / 下方挖。不在小厅、信标厅、梯子 / 竖井、起点附近等特殊格，旁边巷道格没有火把、积水、矿坑、遗落物品。
  - 普通的：墙格只有一面朝巷道、背后是实心岩石，离理想路线（第 1 层取所有破口候选起点的路线）1–8 格；约 60% 在头部高度、40% 在脚部；彼此至少隔 5 格。
  - 薄墙的：第 5 档起，每张图至多 1 处（25% 的图会尝试；因迷宫里 1 格厚、且绕路 4–12 步的墙不多，实测约 1/10 的图真有），只在第 1–2 层；墙格两侧各是一条巷道、绕路比挖穿多走 4–12 步；**总是脚 + 头一对**，挖掉两个才能走过去，从不单独一个脚部薄墙矿。
  - 每层个数（`tier(d).weird`，随档位单调不减；薄墙一对算 2 个；放不下就放能放的）：第 1 层（破口层）d0–9 为 2、d10–19 为 3、d20–28 为 4；第 2 层 d5–9 为 1、d10–28 为 2；第 3 层 d10–19 有 50% 概率 1 个，d20–28 为 1 个再加 30% 概率第 2 个。
- 挖：面朝奇怪的矿石、一直按住朝它的方向键（触屏：按住朝它的方向按钮）约 0.8 s 挖下一块（4 段裂纹），右手出现原创的钻石镐（3D 体素 / 2D 像素）挥动；同一格脚、头都有时先挖头部。松开或转向则进度清零。身上碰到岩浆立即停、在岩浆里不能开始；地下水淹过上半身后按淹没程度变慢，完全淹没（气泡在掉）时不能挖。溺水失控后也不能挖。
- 挖开的格子变成空气（方案 B）：主线程副本与模拟世界（Worker 的 `open` 命令 / 同步后端）都挖开，流体从下一刻起就能流进去；同步模式下确定。开局预跑的公平判定不考虑挖矿（不变）。薄墙一对都挖开后可以走过去。
- 反馈：每块一声明亮的原创合成琶音（受统一音效开关控制）；人物旁冒出"+1"与奇怪的石头图标往上飘并淡出（减少动态时不飘）；HUD 显示奇怪的石头计数（图标 + 数字）。2D 兜底全部一致。
- 转头：经过附近（5 格内、视线不隔岩石）的未挖奇怪的矿石时，身体照常朝移动方向，头转向矿石（离得近时也略微俯仰到脚 / 头高度）；头身夹角最多 ±90°，再大就转回正前方；约 10 rad/s 平滑转动；挑最近的；挖掉后不再看。不影响碰撞与移动。2D 小人的脸朝向同样跟着转。

## 29. 计分（服主定稿）
- 只有胜利计分；失败只显示"挖到奇怪的石头 ×N"、逃出层数等，不计分。
- S = 3,000,000 × 1.1^d × Ft × Fh × Fp × Fo，向下取整。
  - r = max(0.9, (t + 10) / (T + 10))，T = 所选地图的理想路线时间（`idealStats`：`route(M)` 最后一格的 t + 最后一段竖井；竖井时间与游戏共用常量：走进梯子格按住 0.3 s + 淡出 0.3 s + 爬 2.7 s，中间的竖井再加到上一层的淡出 0.3 s。原先漏了最后一段竖井、中间的竖井按 3.2 s 估算，已修正），t = 通关用时；Ft = 0.25 + 0.75 × 2^(−(r − 1) / 0.5)
  - Fh = 0.4 + 0.6 × 最低生命 / 20
  - Fp = 0.9^( max(0, 进坑次数 − 理想路线进坑次数) + 3 × 掉层次数 )
  - Fo = 1 + 0.10 × 奇怪的石头
- 评级不含难度与奇怪的石头：Q = Ft × Fh × Fp，S ≥ 0.75、A ≥ 0.55、B ≥ 0.3，否则 C。
- 显示：4 位一组的分隔 `1234,5678`（`fmtScore`：向下取整、不为负、不用 toLocaleString）。同分时用时短者优先，再比最低生命高，再比奇怪的石头多。
- 调试局（自动驾驶、`?egg-slow`、`?egg-sync`、`?egg-test` 的测试 hook）不计分、不保存（测试用 `scoring(true)` 强制计分）。最佳分存在 `score:<seed>:<cycle>` 键下（{分、用时、最低生命、奇怪的石头、流体落后}），与最佳用时分开。
- 画面模式标记（服主追加）：2D 兜底比 3D 容易玩，所以结算面板版本行（"v183 · 难度 23 / 29 · 3D"）、分享卡片与分享文字都标出 3D / 2D，最佳记录里也存下模式；不影响计分，也不按模式分开存最佳。中途 WebGL 失效且没能恢复时本局记为 2D。
- 流体落后：记录一局里"游戏时间 − 已应用的最新流体刻 / TPS"的最大值（Worker 每跑完一批报告当前刻）。超过 0.100 s 时结算面板多一行"流体最多落后 0.237 秒"（3 位小数）；分数照常保存并正常覆盖最佳（只是为将来跨设备比较留个提示），落后值随最佳记录一起存。
- 结算面板：总分 + 评级 + 新纪录；明细依次为时间、生命、掉坑、奇怪的石头、难度，逐行出现、系数从 ×1.00 数上去（一声比一声高的提示音），难度最后"盖章"，总分滚动上去，评级弹出。动画中任何按键 / 点击只跳过动画、不开新局（动画播完才 endReady）；减少动态时直接显示最终值。宽屏时明细排成两列，360 / 390 宽不溢出，深浅主题都有。

## 30. 分享（服主追加：不做排行榜，成本太高；改为分享）
- 胜利的结算面板上有"分享"按钮（键盘可聚焦；只由用户点击触发，从不自动分享；不影响 endReady 与开新局）。
- 在本地合成一张 1080×1350（4:5）的分享卡片：上面是结局画面（结局的 320×240 离屏画布按整数倍放大），下面是像素风战绩面板：游戏名（与模块 `title` 同一个常量 `GAME_TITLE`，服主改名后自动跟着变）、"v<N> · 难度 x / 29"、4 位分组的分数与评级、用时、最低生命、奇怪的石头 ×N、流体落后提示（显示时）、链接。卡片上不含任何个人信息。
- 文字：「我在悠然MC官网 v<N>（难度 x/29）逃出了矿井：<分数> 分 <评级>，挖到奇怪的石头 ×n <链接>」（调试局没有分数时写用时）。

## 31. 触屏操作：摇杆 / 方向键、操作区左右、横屏全屏（服主追加）
- 触屏（pointer: coarse，或方向键区显示时）在操作区旁有两个小开关：「操作方式：摇杆 / 方向键」（默认摇杆）和「操作区：左 / 右」（默认左，左撇子可放右边）。选择记在宿主存储里（`ctl`、`ctlSide`，读写失败就用默认）。桌面键盘不变。
- 摇杆：底座固定在原来方向键的位置（竖屏在画面下方，横屏在画面一侧），拇指头跟着手指、最多到底座边缘；指针捕获（拖出底座也照样控制）；松开回中、停下。方向是模拟量，按屏幕方向映射，与方向键完全一致（往上推 = ArrowUp）。死区为半径的 15%，15%–45% 之间速度线性增大，再往外全速。走得比全速慢不影响公平（预跑按全速）。
- 需要"一个格子方向"的动作（爬出矿坑、深坑里换格、挖奇怪的矿石）取摇杆的主轴方向，与该方向夹角 ±45° 以内都算朝它按住。

- 外观：像素风圆盘（SVG、crispEdges），底座半透明，深浅主题都有。
- 横屏全屏（宿主实现，见 CONTRACT「横屏全屏」）：root 带 `.egg-fs` 时，本游戏铺满 root 的可用高度，画面 4:3 按高度缩放、水平垂直居中、四周留 8px 让绿色描边完整可见；底部"用时"行隐藏（HUD 已有），开始 / 继续按钮浮在画面下沿；背景透明，露出宿主随主题变化的 `--bg`（浅色近白、深色近黑），摇杆 / 方向键 / 开关用主题色变量；操作区放在左 / 右边距里，画面两侧至少留 136px，避开宿主右上角约 110×96px 的"退出全屏"/音效按钮区，操作区在右边时贴底放；结算面板盖在画面中间、超高可滚动。844×390、932×430 下 HUD、QTE、结算面板与分享按钮都在视口内。尺寸变化由 ResizeObserver 跟踪，另监听 fullscreenchange。

## 32. 体温（服主设计，含后续追加）
- 动机：地下水比岩浆快得多，高手在水图上也躲不开涉水，岩浆却几乎能完全避开；体温让涉水有代价。另：高档位通关偏容易，体温是加难的主要手段。
- 模型（`breachCore` 里的 `thermoStep`，主线程与预跑共用）：两室——核心 Tc（显示，正常 37.0）与外壳 Ts（不显示，正常 34）。外壳与环境交换热量，核心只与外壳交换，所以有滞后：出水以后核心还会继续降一阵（后降），到最低点再回升。时间按游戏节奏压缩，曲线形状接近真实。
  - 浸没深度：按脚格 / 头格的流体层数算水深 → 脚踝 / 膝 / 腰 / 胸 / 没顶，按散热面积加权（躯干比腿重要）；躺着时整个人贴在脚格里。
  - 湿身：湿度取最近一次最深的浸没，随时间变干（水图 30 s、岩浆图 5 s）；湿着在空气里继续蒸发降温。
  - 水温按档位：14 ℃ → 7 ℃（原定高档约 4 ℃；按实测改成 7 ℃，见下面的标定）。岩浆图的积水是 33 ℃ 的温水：能降温，但只降到正常，不会因此失温。
  - 寒战：Tc < 36.5 ℃ 时产热，到中度失温（< 32）停止 → 降温加快。出汗：Tc > 37.5 ℃。
  - 岩浆：按离最近岩浆（本层脚 / 头高度与坑底）的距离辐射加热，约 4 格（档位 3.2 → 4.2 格）以外为 0；碰到岩浆急剧升温（伤害不变）；离开后很快降下来。
  - 标定：中档（第 14 档）稳定齐腰深约 22 s 到中度失温、约 40 s 到重度失温（完全淹没会先溺水）。实测（真实地图 + 预跑选图、每档 8 张图）：第 14 档理想路线多数到轻度、少数到中度；第 24–28 档理想路线一半轻度、一半中度，1.3 倍时间的路线大多到重度。热的整体更温和：贴着岩浆站十几秒才到轻度过热，碰到岩浆才会很快中暑。
- 阶段：失温 轻度 35–32（只提示：发抖、牙齿打颤）/ 中度 32–28（走路 ×0.9→0.82（随档位）、爬出矿坑的长按 ×1.15→1.25（另封顶多 1 s）、动作变迟缓、画面发灰、人物带霜色）/ 重度 < 28 倒下。过热 轻度 38.5–39.5（出汗）/ 中度 39.5–40.5（同样减速、热浪扭曲，减少动态时不扭曲）/ 中暑 > 40.5 倒下。
- 身体信号（不看 HUD 也读得出）：冷时呼出白气（越冷越频繁、越大），湿时身上滴水（随湿度，干了就停），轻度失温发抖（中度不再发抖，改为动作迟缓），中度起人物带淡淡的霜色，热时出汗 + 人物周围热浪。减少动态时：不抖、不扭曲，白气 / 水滴 / 汗用静止的小图，颜色照常。
- HUD：右上心形左边一个彩色圆点（黄 = 正常 → 蓝 = 冷 / 红 = 热，渐变），圆点左边是核心温度（"36.8°C"），最左边是手里火把（点着 / 没点着的木棍）；轻度起第二行加图标（雪花 / 火焰）与阶段名（轻度失温 / 中度失温 / 重度失温、轻度过热 / 中度过热 / 中暑），不只靠颜色；温度旁的箭头表示体温变化趋势（试玩后统一，所有原因都一样）：在升 ↑（暖色）、在降 ↓（冷色）、稳定时不显示；按平滑后的 dTc/dt（τ ≈ 1 s）判断，超过 0.02 ℃/s 才出现、降到 0.008 ℃/s 以下才收起，不闪。挨着墙上火把时人物身边另有一圈暖光。3D / 2D 相同。
- 结算面板多一行"最低体温 / 最高体温"（取偏离正常更多的一侧），只显示，不计分。
- 手里火把（服主，后改生命周期）：中度失温时可以用来取暖（桌面 Shift，HUD 提示「Shift 用火把取暖」；触屏出现按钮），引导约 2.5 s（站着把火把凑到胸前，一动就中断，火照样烧完）。引导中 HUD 进度条上方写「取暖中…别动」，触屏的按钮也变成「取暖中…别动」；第一次出现取暖提示时另有约 5 s 的小提示（要原地站着、一动就中断；火灭了可以在墙上的火把旁重新点着）。按脚下格的水层数（8 = 满格）：≤ 3 层快速升温（目标 33.5 ℃，升温速度随档位 2.4 → 1.4 ℃/s）；4–5 层只止住降温；任何时候 > 5 层火被浇灭、停止取暖。不论哪种结果火都灭了，但不扔：手里留着一根没点着的木棍（烧黑的头），没有随身的光（暗区里更暗，只剩身边约 1 格微光）。
- 重新点火（服主，后改操作）：复用取暖的 Shift / 动作按钮。手里火把灭着、够得着一支点着的墙上火把（身边 3×3 格内、距离 ≤ 0.62 格、不隔岩石）时，桌面 HUD 提示「按住 Shift 取火」，触屏动作按钮的文字变成「取火」；在提示出现时按住 Shift（或按住按钮）约 1.5 s 点着（光回来、可以再取暖），人物原地站住，脚下出现进度条。松开 / 有方向输入（走开）→ 进度清零；那支墙上火把在这期间被水浇灭、或自己脚下这格水 > 5 层 → 点不着。方向键 / 摇杆只管走路，不再「朝着火把按方向键」取火（原做法会让火把灭着的玩家每经过一支墙上火把就被定住）。动作键优先级：爬起来 > 取暖 > 取火；三者互斥（取暖要求火把点着，取火要求火把灭着且没倒下，爬起来要求倒下），所以火把灭着时不会与取暖冲突。取火不消耗墙上的火把，次数不限；墙上的火把会被淹灭，所以矿井越淹，火越难找。岩浆图也一样（只关系到光，取暖只在水图上有用）。HUD 的火把图标分点着 / 没点着。
- 手里的火把碰到水就灭（服主追加）：站着 / 走 / 爬梯 / 扒坑沿时脚下格 > 5 层或头格有水；躺着 / 爬时身上任何水。一声嘶 + 一小股蒸汽，光立刻没了，HUD 图标变成没点着；之后照样可以重新点火。岩浆图的水同样适用。
- 墙上火把（服主追加；试玩后统一为两种地图相同）：身边 3×3 格内、同一层、不隔着岩石，被动加热，不用按键、不消耗。越接近 / 高于正常越慢：核心额外升温 ∝ (44 − Tc)²（44 ℃ 高于中暑线，所以一直待着也能慢慢热到过热：约 10 s 到轻度过热，之后基本停在轻度）；冷的时候回暖快得多（30 → 33.5 ℃ 约 6 s，比手里火把慢）。从旁边正常速度走过（约 0.7 s）只升约 0.1 ℃，只是"久待的慢威胁"。水位规则同手里火把（≤ 3 层加热、4–5 层只止住降温、> 5 层无效）。流体淹到火把那格时火把永久熄灭（光也灭，一声嘶 + 一小股烟）——水越涨越少。在水图上也算急救来源（失温躺在旁边、身上不超过 3 层水时慢慢回到轻度），也是手里火把重新点火的火源。预跑不模拟墙上火把。
- 手里的火把本身不加热也不提供任何被动热量，只有中度失温时按 Shift / 按钮主动取暖（含重度急救）。
- 触屏动作按钮（用火把取暖 / 爬起来）：放在不管移动的那只手旁边——竖屏在操作区里与摇杆相对的一侧（开关旁边），横屏在画面另一侧的下角，横屏全屏在另一侧的边距里、贴底（避开宿主右上角按钮区）；跟随操作区左右设置。按钮不算 QTE 的点击、不开局。
- 重度（服主）：倒下——跪下 → 顺着巷道侧倒（身体经过的格都要是平地：不进墙、坑、梯子；哪个方向都躺不下就背靠墙坐倒）；在梯子上先滑到梯子底（回到本层）再倒下；在坑里蜷在坑底；扒着深坑沿时手一松掉下去、落地后再倒下。倒下过程不响应输入。之后能爬（约走路的 30%，不能进矿坑 / 上梯子），爬的时间窗随档位 7 → 5 s。急救：
  - 地下水图：身上没有一点水（躺着那几格 0 层）且手里火把点着 → Shift / 按钮取暖，把核心拉回轻度；任何水碰到他都会中断 / 不能用。墙上火把也能慢慢救回来。
  - 岩浆图：爬进水里（积水或任何水）→ 快速降温，躺得越久降得越多，降到正常为止；岩浆仍可能追上来。
  - 正在急救时时间窗暂停。回到轻度（或更好）后出现「Shift 爬起来」（触屏同一个按钮位置）→ 起身动画 → 恢复操作。
  - 时间窗用完没被救：失温 / 中暑结束过程，与溺水一样失去控制约 3.5 s：失温是四周结霜、画面灰蓝，中暑是画面发白 + 热浪 + 耳鸣，都有越来越慢的心跳；死因"失温" / "中暑"。
  - 趴着时口鼻贴近地面：头所在格水深 ≥ 3 层就憋气。趴着溺水又失温时两种结束效果叠加，死因"溺水 · 失温"。
- 窒息（服主追加）：头所在的那一格（趴着 = 头那端贴地的格；站着 = 头格）因为流体凝固（岩浆 + 水 → 石头 / 圆石 / 黑曜石）变成实心时立即窒息：与溺水相同的结束过程（失去控制、黑暗收拢、声音发闷、心跳变慢；与冷 / 热效果叠加），死因"窒息"。趴着时只有身体那格变实心 = 卡住爬不动，冷 / 热与时间窗照走。人物埋在石头里时照常用透视轮廓画出来。
- 公平（预跑）：理想玩家按路线走（同样的涉水减速、中度减速、爬坑变慢），每两刻读模拟世界里身体两格的流体推进体温：全程不能到重度失温 / 中暑（不用火把），中度阶段累计的延误也不能让任何一格的到达时间超出该格的危险截止时刻（到达时间 × slack + 2 s）。不满足就像流体不公平一样换破口 / 换图。体温失败多出现在高档：第 28 档最多试 5–6 张图，预跑最长约 1.7–2.2 s（原约 1.2 s），各档仍 100% 选到公平的图。
- 不改计分，不按画面模式 / 体温分开存最佳。减少动态、音效开关、endReady / 松键规则、摇杆 / QTE、横屏全屏、2D 兜底都照常。

## 33. 试玩反馈（服主转达）
- 出口一侧不再固定：原来第 1 层出口总在东、第 2 层总在西、第 3 层总在东（`exitSide` 从东开始交替）。现在第 1 层出口在哪一端由种子决定（独立的随机数流，东西约各一半；抽到东边时迷宫与原来完全相同），破口候选放在另一端（出口在东 → 西侧 60% 的支巷，出口在西 → 东侧 60%），所以起点到出口的路程分布不变；往上每层的出口都在与入口（下层竖井口）相对的一端——同一端的话入口和出口只隔一两条主巷道，这一层就几乎没有路可走。确定性（由 seed、档位、regen 决定，进地图指纹）。破口距离等档位参数与开局预跑照常。
- 出口的告示牌：新玩家把右侧（东边）出口的梯子当成普通摆设。每个出口小厅（梯子所在的站点小厅）北墙、南墙正中各挂一块空白告示牌（梯子总是东西朝向，牌子挂在南北墙上，出口在哪一端都一样）。原创像素：木板 + 两道板缝 + 顶上两个挂钩；3D 另有一圈不受光照的暗暖色描边、2D 光照后再描一圈边，暗处也认得出。牌子挂在岩石墙面的头部高度（b + 2 那格；原先挂在脚部高度，会和靠在同一面墙下的箱子穿插，服主要求上移一格），面朝小厅，不占格、不挡路；这两格墙不放奇怪的矿石（实际上小厅墙本来就不会被选中，规则只是兜底，不改变任何地图）；流体照常流过（像含水的梯子），会被淹没但不会被冲掉。默认镜头（朝北俯视）下北墙那块正对镜头；南墙那块背对镜头，3D 里要走近、前墙渐隐时才看得到，2D 俯视两块都看得到。

## 34. 险图（服主决定；不对玩家显示）
- 理由：开局预跑只认证一条理想路线（不挖矿、不重新点火、不堵水、不借信标），系统越来越多，被它拒掉的图不一定打不过——留一部分给高手。
- 只在高档（d ≥ 22，显示 23/29 起）：每个版本按种子决定是否"险图"（确定性，`riskyOf(seed, d)`），概率随档位单调：第 22 档 5% → 第 28 档 25%（`tier(d).risky`）。
- 险图的预跑：先照常在原图（regen 0）的破口候选里做严格公平测试；通过就和平常一样。不通过时**不换图**，只要"底线"成立就保留原图：按理想路线走（与体温预跑同样的速度规则），被流体追上（身体两格达到危险层数）或到重度之前，已经走完 ≥ 60% 的路线时间（f ≥ 0.6），且起点那一格在开头 1 s 内（人还没走开）没被淹。原图试过的各个破口里取 f 最大的。底线也不成立就照常换图（regen 1, 2…），所以真正没希望的图不会发出去。非险图的选图规则完全不变。
- 计分：险图上理想时间放宽为 T_eff = T × rT，rT = 1 + 0.5 × (1 − f) / 0.4，夹在 [1.15, 1.5]；严格测试通过时 rT = 1。时间系数、评级 Q 与结算面板的"理想 xx s"都用 T_eff。rT 在预跑里算出（Worker / 同步相同），随破口与 regen 一起交给主线程，进地图指纹。
- 不显示：没有任何标签、HUD、结算面板或分享标记，玩家自己去发现。

## 36. 理想路线按步数最短，不改为时间最短（服主决定）
- `route()` 沿 `distExit` 逐格下降，取的是步数最少的路线；坑、积水的耗时不影响选路，高档图上会穿过不少坑，因此理想时间 T 偏长，熟练玩家（绕坑、借信标 ×1.3）可以跑进 T，如 /v-8097 服主 103.5 s 快于 T≈107 s。
- 服主决定保持现状：理想时间本来就是"看图"的参考，公平判定用一条偏慢的路线证明"至少有路可活"也更保守；不改为 Dijkstra，也不把信标算进理想路线。
